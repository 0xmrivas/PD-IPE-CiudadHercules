## Cómo funciona

Todas las PD tienen el mismo índice, el de las PD del centro. Cada apartado se
busca en estas carpetas, por este orden, y **entra el primero que exista**:

`pd/<programación>/` → `modulos/<módulo>/` → `ciclos/<ciclo>/` → `comun/`

Así, si un apartado común tuviera que ser distinto en una PD, basta con copiarlo
a su carpeta de `pd/` y cambiarlo allí.

Dentro de cualquier archivo:

- `<!-- incluir: fragmento -->` inserta `fragmento.md`, buscado con la misma cascada.
- `<!-- por-grupo: fragmento -->` inserta `grupos/<grupo>/fragmento.md` de cada grupo de la PD.
- `<!-- tabla-grupos: fragmento -->` une la tabla «Dato | Valor» de `grupos/<grupo>/fragmento.md`
  de cada grupo en una sola tabla, con una columna por grupo (así salen los datos de los grupos).
- `{{ciclo}}`, `{{modulo}}`, `{{codigo}}`, `{{horas}}`, `{{grupos}}`… se sustituyen por
  los datos de `manifest.yml`; dentro de un fragmento de grupo, `{{grupo}}` y
  `{{letra}}` son los de ese grupo.
- `<!-- ficha-modulo -->` pone la ficha del módulo (código, ciclo, grupos, horas, docente).
- `<!-- tabla-relacion-ra -->` genera la relación RA–criterios–UD a partir de las
  tablas de unidades y de criterios.
- Lo que va entre corchetes, `[Así]`, cuenta como pendiente y sale en gris en el PDF.
- Los comentarios `<!-- … -->` explican qué escribir y no salen en el PDF.

## Generar en local

```bash
python3 -m pip install -r requirements.txt   # PyYAML
python3 -m unittest discover -s tests
scripts/build-pdf.sh                          # todas (Pandoc >= 3.11 y Typst >= 0.14)
scripts/build-pdf.sh ipe1-gm                  # solo una
```

Los PDF quedan en `dist/`; en GitHub, la action los publica en `programaciones/`.

El motor (validación, tablas generadas, filtros de maquetación) procede del
repositorio de la PD del Departamento de Informática del IES Rafael Alberti.
